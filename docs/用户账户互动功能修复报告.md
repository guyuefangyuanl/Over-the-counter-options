## 📋 执行摘要

本次修复针对用户账户互动功能存在的登录失败、API超时、用户信息同步等问题进行了全面诊断和修复。主要解决了以下核心问题：

1. **API超时问题**：云托管Flask服务响应超时导致用户资料获取失败
2. **登录响应解析问题**：小程序端登录响应解析逻辑不完善
3. **Token机制不一致**：云函数和后端使用不同的Token格式
4. **用户统计API性能问题**：复杂查询导致请求超时

---

## 🔍 问题诊断详情

### 1. 问题表现

根据错误日志分析，发现以下问题：

```
获取用户资料失败 Error: 服务器内部错误，请稍后重试
API请求失败 GET https://flask-ym1v-.../api/v1/trade/positions/statistics: 
{errMsg: "request:fail timeout", errno: undefined}
```

### 2. 根本原因分析

| 问题 | 根本原因 | 影响范围 |
|------|----------|----------|
| API超时 | 云托管服务响应慢，默认10秒超时不够 | 用户资料、持仓统计等接口 |
| 登录失败 | 响应解析逻辑复杂，未统一处理错误 | 微信登录、游客登录 |
| Token不一致 | 云函数使用Base64，后端使用JWT | 跨服务认证失败 |
| 统计API慢 | 同步查询多个集合，无超时保护 | 用户统计接口 |

## 🔐 双Token机制说明

### 机制设计

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  Access     │     │   Refresh    │     │   用户      │
│  Token      │     │   Token      │     │   信息      │
│  (15分钟)   │     │   (7天)      │     │             │
└──────┬──────┘     └──────┬───────┘     └──────┬──────┘
       │                   │                    │
       ▼                   ▼                    ▼
┌─────────────────────────────────────────────────────┐
│                  小程序本地存储                      │
└─────────────────────────────────────────────────────┘
```

### 刷新流程

1. **Token过期检测**: 每次请求前检查 `tokenExpiry`
2. **自动刷新**: 收到401错误时自动调用 `/auth/token/refresh`
3. **并发控制**: 使用 `isRefreshing` 标志避免重复刷新
4. **队列机制**: 刷新期间的请求排队，刷新成功后重试
