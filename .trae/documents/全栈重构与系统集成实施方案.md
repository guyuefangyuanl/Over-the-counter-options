# 全栈重构与系统集成实施方案

本方案旨在通过系统性的重构，统一后台管理系统与微信小程序的技术架构，实现数据互通、权限统一和业务逻辑的一致性。

## 1. 项目目标
- **架构清晰化**：后端采用分层架构（Controller-Service-Model），前端组件化。
- **接口标准化**：建立统一的 RESTful API 规范，复用后端逻辑服务于双端。
- **数据一致性**：确保管理端配置（如板块、客户分组）与小程序端展示实时同步。
- **安全稳固**：统一认证鉴权机制（JWT + 微信登录），完善 RBAC 权限控制。

## 2. 技术架构与选型

### 2.1 后端 (Python/Flask)
- **核心框架**：Flask (保持不变，升级结构)
- **数据库**：MongoDB (本地/云端双模适配，统一 Model 层)
- **架构模式**：
  - `routes/`: 路由定义与参数校验 (Web/Admin API, App API 分离但共用 Service)
  - `services/`: 核心业务逻辑 (如 `QuoteService`, `OrderService`)
  - `models/`: 数据持久化与 Schema 定义
  - `utils/`: 通用工具 (Auth, Logger, Response)

### 2.2 前端 (React Admin)
- **框架**：React + TypeScript + Vite
- **UI 库**：Ant Design
- **状态管理**：React Context / Hooks
- **网络层**：Axios 封装 (统一拦截器，处理 Token 和错误)

### 2.3 小程序 (Native WeChat)
- **框架**：原生小程序 + Vant Weapp (UI)
- **网络层**：`wx.request` Promise 封装 (支持拦截器、自动登录重试)
- **数据流**：简单的全局 Store (App.globalData) + 页面级 Data

## 3. 模块划分与重构策略

| 模块 | 功能描述 | 重构策略 | 优先级 |
| :--- | :--- | :--- | :--- |
| **认证中心 (Auth)** | 登录、注册、Token管理 | 统一 `routes/auth.py`，支持 Admin 账号与微信 OpenID 映射关联 | **P0 (最高)** |
| **基础配置 (Config)** | 费率、系统参数 | 抽取 `ConfigService`，提供管理端配置接口与小程序读取接口 | P1 |
| **客户管理 (User)** | 客户信息、分组、鉴权 | 完善 `CustomerModel`，打通微信用户与 CRM 客户表 | P1 |
| **行情中心 (Quote)** | 标的、报价、历史数据 | 优化 `QuoteService`，实现行情缓存与实时推送逻辑 | P1 |
| **交易核心 (Trade)** | 询价、订单、持仓 | 重构订单状态机，确保双端状态同步 (如管理端确认订单，小程序端即时更新) | **P0** |
| **板块管理 (Group)** | 自选股、分组管理 | 复用已修复的 `GroupModel`，增加小程序端的展示适配 | P2 |

## 4. 后台与小程序集成方案

### 4.1 API 接口规范
- **路径规范**：
  - 管理端：`/api/v1/admin/...` (需 `admin` 角色)
  - 小程序：`/api/v1/app/...` (需 `user` 角色)
  - 公共：`/api/v1/public/...`
- **响应格式**：统一为 `{ code: 0, message: "OK", data: ... }`

### 4.2 联调与数据同步
- **用户身份互通**：小程序登录生成 JWT，Payload 包含 `openid` 和 `customer_id`。管理端通过 `customer_id` 关联业务数据。
- **实时性保障**：对于询价回复、订单状态变更，后端提供轮询接口或 WebSocket (后续迭代) 支持。

## 5. 实施时间表 (预计 2 周)

### 第一阶段：基础架构重构 (3天)
1.  **Day 1**: 搭建后端分层目录结构，迁移 `auth` 和 `config` 模块，统一 `Response` 格式。
2.  **Day 2**: 封装前端 (Admin/App) 的网络请求层，实现统一的错误处理和 Token 注入。
3.  **Day 3**: 完成统一认证中心，打通小程序一键登录与后端 User 表的创建/关联。

### 第二阶段：核心业务迁移 (5天)
1.  **Day 4-5**: 重构 **行情与板块** 模块。管理端可配置板块，小程序端读取展示。
2.  **Day 6-7**: 重构 **询价与交易** 模块。实现“小程序发起询价 -> 管理端回复 -> 小程序确认 -> 生成持仓”的全链路。
3.  **Day 8**: 完善 **持仓管理**。确保管理端录入/修改的持仓数据能准确同步至小程序账户页。

### 第三阶段：集成测试与优化 (2天)
1.  **Day 9**: 双端联调。模拟真实业务流程，验证数据一致性。
2.  **Day 10**: 性能优化 (索引优化、缓存策略) 与 Bug 修复，部署上线。

## 6. 质量保障
- **单元测试**：后端核心 Service 层覆盖率 > 80%。
- **集成测试**：针对核心链路 (登录->询价->交易) 编写自动化测试脚本。
- **回滚机制**：数据库变更提供兼容模式，代码支持灰度发布。
